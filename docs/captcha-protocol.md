# Bilibili Geetest v3 Click CAPTCHA Protocol (Sanitized)

This document describes the observed Geetest v3 click CAPTCHA flow used by Bilibili web login.
All secrets, cookies, tokens, phone numbers, and session values have been removed.

## Flow Overview

```text
1. GET  /x/passport-login/captcha
   -> returns gt and challenge

2. GET  https://api.geetest.com/get.php?is_next=true&type=click
   -> returns captcha image path and click mode metadata

3. GET  https://static.geetest.com/captcha_v3/.../word/<hash>.jpg?challenge=<challenge>
   -> actual CAPTCHA image

4. Final submit (example: login endpoint)
   POST /x/passport-login/web/login
   Body fields:
     validate=<geetest_validate>
     token=<geetest_token>
     seccode=<geetest_validate>|<suffix>
     challenge=<challenge>
```

## Important Notes

- The image itself contains the prompt text and candidate characters.
- OCR must:
  1. Read the prompt text order.
  2. Detect candidate character positions.
  3. Output click coordinates in prompt order.
- The final `validate` value is generated by the Geetest front-end JavaScript,
  not directly by the click coordinates.
- To generate a valid `validate`, either:
  - Run the Geetest front-end in a WebView2 / browser and simulate clicks, or
  - Reimplement the Geetest encryption logic (not recommended; may change).

## Repository Implementation

- `CaptchaOcrService.cs`: local OCR using Tesseract.
- `GeetestCaptchaService.cs`: fetch CAPTCHA image and match prompt order.
- `GeetestWebViewAutomation.cs`: WebView2-based automation scaffold.

No third-party CAPTCHA-solving platform is used.
